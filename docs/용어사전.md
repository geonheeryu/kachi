| story 요약 | Story Summary | story 하나의 요약 버전 하나. 직전 버전 요약과 새로 붙은 기사를 함께 넣어 만들고, `(storyId, version)`이 멱등 키다. | 034 |

| story 격리 | Story Quarantine | 입력 탓 실패가 연속으로 임계치에 닿은 story를 요약 대상에서 제외하는 장치. 운영자가 수동으로 해제한다. | 034 |

| 시장 데이터 | Market Data | 종목, 지수, 가격 등 뉴스 해석에 필요한 금융 시장 데이터. | |
| 키워드 확장 | Keyword Expansion | 사용자의 키워드를 AI가 관련 검색어로 확장하는 작업. | |
| 요약 | Summary | 수집된 뉴스 묶음을 AI가 사용자에게 읽기 쉬운 형태로 정리한 결과. | |
| AI 실행 | AI Run | 키워드 확장 또는 뉴스 요약 작업 한 번의 실행 기록. | |
| LLM API 규격 | LLM API | LLM 요청·응답 JSON의 모양. 코드가 분기하는 유일한 축이며 규격마다 adapter 하나가 있다. | 030 |
| LLM 제공자 | LLM Provider | 한 계정으로 부르는 LLM 서비스 하나. 회사와 계정이다. 같은 규격을 여러 회사가 내므로 규격과 별개 축이다. | 030 |
| LLM 모델 | LLM Model | 한 제공자에서 부르는 모델 하나. wire id와 요청 옵션을 함께 갖고, 실호출 검증을 통과한 것만 코드에 둔다. | 030 |
| LLM 용도 | LLM Use | 앱이 LLM을 부르는 이유. 뉴스 요약, story 요약, 키워드 확장이며 용도마다 후보 모델의 순서가 따로 있다. | 030 |
| 후보 모델 | Candidate | 한 용도에서 순서대로 시도하는 모델 목록. yaml이 정한다. 여기 없는 모델은 클라이언트도 서킷도 만들지 않는다. | 030 |
| 프롬프트 버전 | Prompt Version | AI 응답 재현성과 변경 추적을 위해 프롬프트 계약에 붙이는 버전. | |
| 감성 | Sentiment | 뉴스 또는 요약 결과가 긍정, 중립, 부정 중 어디에 가까운지를 나타내는 값. | |
| 요약 워터마크 | Summary Watermark | 뉴스 요약 처리를 끝낸 지점. 다음 실행 window의 시작 기준이 되며 앞으로만 전진한다. | |
| 요약 윈도우 | Summary Window | 한 번의 요약 실행이 처리하는 뉴스 수집 구간. watermark에서 overlap만큼 물러나 시작한다. | |
| 틱 | Tick | scheduler가 주기마다 시작하는 요약 실행 한 번. 실패한 구간은 다음 tick이 이어서 재처리한다. | |
| 뉴스 해시 | News Hash | 키워드와 뉴스 id 묶음으로 계산하는 요약 중복 저장 방지 키. | |
| 키워드 격리 | Keyword Quarantine | 연속 실패가 임계치에 도달한 키워드를 요약 대상에서 제외하는 장치. 운영자가 수동으로 해제한다. | |
| 건너뜀 | Skip | 실패가 아니라 조치할 것이 없어 처리하지 않은 결과. 요약할 뉴스가 없거나 호출할 수 있는 후보 모델이 없을 때 기록한다. | |
| 서킷 브레이커 | Circuit Breaker | 외부 호출의 연속 실패·느린 호출 비율이 임계치를 넘으면 호출을 차단하고 빠르게 실패시킨 뒤, half-open 탐색으로 복귀하는 장치. 프로젝트 문서·주석에서는 "서킷 브레이커"로 통일한다. | 018·021 |
| LLM 실패 분류 | LLM Failure | LLM 호출 실패를 표준 코드와 책임·지속 두 축으로 보존하는 값. 서킷 기록, hold, 격리 카운트, 조기 중단 판단의 기준. | 021·030 |
| 실패 책임 | Attribution | LLM 실패의 책임이 어디 있는가. 입력(이 키워드의 요청·응답), 모델, 제공자(계정과 endpoint), 없음(가드가 호출 전에 막음) 넷 중 하나. | 030 |
| 쿨다운 | Cooldown | 429를 받은 모델이 Retry-After만큼 후보에서 빠지는 상태. 비율로 열리는 서킷과 별개다. | 021 |
| 보류 | Hold | 404를 받은 모델이나 401·402·403을 받은 제공자를 한동안 후보에서 빼는 상태. 서킷과 달리 한 건으로 확정되고, 만료되면 한 번 다시 시도한다. | 021·030 |
| 실호출 검증 | realTest | 설정된 후보 모델을 실제 제공자에 불러 존재와 생성 계약을 확인하는 별도 소스셋의 테스트. `./gradlew test`에 섞이지 않는다. | 030 |
| 임베딩 모델 | Embedding Model | 텍스트 1개를 벡터 1개로 바꾸는 모델(bi-encoder). 기사마다 한 번 계산해 색인에 넣고 후보를 찾는다. 생성형 LLM이 아니다. | 031 |
| 판정기 | Judge (cross-encoder, reranker) | 텍스트 2개를 함께 읽고 같은 사건인지 점수 1개를 내는 모델. 임베딩 후보 중 회색 구간을 확정한다. 문장을 생성하지 않는다. | 031·033 |
| 벡터 색인 | Vector Index | 임베딩 벡터를 저장하고 최근접을 찾는 저장소(Qdrant). 모델이 아니고 정본도 아니다. story-service Mongo의 임베딩에서 재구축할 수 있는 파생 캐시다. | 031 |
| 골드셋 | Gold Set | 사람이 "같은 사건인가"를 라벨링한 기사 쌍 묶음. 임계값과 모델을 고르는 측정 기준이며 회귀 테스트로 남는다. | 031·033 |
| TDT | Topic Detection and Tracking | 뉴스 기사를 사건 단위로 묶고 추적하는 정보검색 과제. 첫 보도 탐지·같은 사건 판정·후속 추적이 이 프로젝트의 story 조립과 같은 틀이다. | 031 |
| 알림 | Notification | 요약 결과를 Slack, Discord, Telegram 등 외부 채널로 발송하는 메시지. | |

| 구독 | Subscription | 사용자가 canonical 키워드를 어떤 채널로 받을지 등록한 것. 채널 바인딩이 ACTIVE인 채널만 수신자 조회에 나온다. | 026 |
| fan-out | Fan-out | 이벤트 1건을 수신자 x 채널만큼의 알림 요청으로 늘리는 일. 문서·주석에서는 "펼치기"가 아니라 fan-out으로 통일한다. | |
| 라우팅 | Notification Routing | ai 이벤트 1건을 수신자 x 채널만큼의 알림 요청으로 fan-out하는 일. notification-routing이 맡는다. | 027 |

| 발송 이력 | Notification History | 알림 요청, 발송 성공, 발송 실패, 재시도 결과에 대한 기록. | |
