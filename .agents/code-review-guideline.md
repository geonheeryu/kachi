# 지침 리뷰 기준 (kachi)

`pr-guideline-reviewer` 에이전트가 diff를 읽기 전에 보는 파일이다. 지침 리뷰의 등급, 소명, 판단 항목은 이 파일이 원본이다. 절차와 응답 형식은 에이전트 정의에 있다.

리뷰어의 역할은 문서에 적힌 kachi 규칙의 위반을 찾는 것이다. 근거 절을 인용할 수 없으면 P0·P1로 지적하지 않는다. 경쟁 조건이나 자원 누수 같은 범용 결함은 같은 시점에 `pr-defect-reviewer`가 `.agents/pr-review-common.md`로 따로 보고, PR 뒤에 검토 봇이 다시 본다.

## 등급

| 등급 | 붙이는 경우 | 내려가는 경우 |
| --- | --- | --- |
| P0 차단 | 아래 "P0으로 보는 것"의 항목. 데이터 정합성 손상, 중복 발송이나 유실, 비밀 값 노출, 발송 경로의 특수 분기다 | 코드를 고쳐야 내려간다. 소명으로 내려가지 않는다 |
| P1 수정 필요 | 아래 "P1로 보는 것"의 항목이나 그 항목이 가리킨 절에 적힌 규칙의 위반 | 고치거나, 작성 측이 근거를 달면 "소명됨" |
| P2 권장 | 규칙 위반은 아니지만 고치면 읽기 쉽거나 안전해지는 것 | 판정을 막지 않는다 |
| 질문 | 근거 절이나 코드로 판단할 수 없는 것 | 사람이 답한다 |

- P0·P1에는 근거 절(문서 경로와 절 제목)을 붙인다. 근거 절을 대지 못하면 P2나 질문으로만 낸다.
- 소명의 근거로 인정하는 것은 ADR, 문서 절, 측정값, 테스트다. "의도한 것"이라는 말만으로는 받지 않는다.
- 소명된 P1은 응답의 소명 목록에 남긴다.
- P0은 리뷰어가 내리지 않는다. 사람이 P0을 받아들이는 방법은 리뷰 판정과 무관하게 진행을 지시하는 것이다.
- 같은 위반이 여러 곳이면 지적 하나에 위치를 모두 적는다.
- 변경 파일 밖의 위반은 이번 diff가 원인일 때만 같은 등급으로 지적한다. diff와 무관하게 전부터 있던 위반은 지적하지 않는다.
- task phase 스펙과 저장소 문서가 부딪히면 등급을 정하지 않고 질문으로 올린다.

## 회차

- 회차는 리뷰를 실행한 번호다. 1회차와 2회차의 지적은 작성 측이 고치거나 소명한다.
- 2회차 응답에 남은 P0·P1은 더 왕복하지 않고 사람에게 올린다.
- 3회차 이상으로 불리면 새 지적을 P0만 내고, 남은 P0·P1을 질문에도 적어 사람 확인을 요청한다. 판정은 남은 건수대로 둔다.

## 판정

"남은" 지적은 이번 회차의 새 지적과, 이전 지적 가운데 해결되지도 소명되지도 않은 것이다.

- 차단: 남은 P0이 있다.
- 수정 필요: 남은 P0이 없고 남은 P1이 있다.
- 통과: 남은 P0과 P1이 없다. P2와 질문은 통과를 막지 않는다. 통과는 사람의 승인을 대신하지 않는다.

## 판단 항목

항목마다 핵심 규칙 한 줄과 규칙의 원문이 있는 절을 적었다. 한 줄은 찾기 위한 요약이고, 판정은 원문 절을 읽고 한다. 한 줄과 원문이 다르면 원문이 맞다.

ArchUnit(`src/test/.../architecture/ArchitectureTest.kt`)이 검사하는 계층 의존 방향, 패키지 순환, 포트·어댑터·컨트롤러·repository·`@ConfigurationProperties`의 위치는 보지 않는다. 기계로 검사할 수 있는데 검사가 없는 규칙의 위반은 지적하고, "ArchUnit 후보"에도 적는다.

### P0으로 보는 것

- 외부 side effect 뒤의 결과 확정은 전이 전 인스턴스의 claim을 기대값으로 하는 저장소 CAS다. 전이 전에 값을 따로 떠 놓지 않는다. 원문: `docs/개발가이드.md` 도메인 모델 관례, ADR 024.
- 발행과 발송은 뒤따르는 상태 저장이 실패해도 중복 발송이나 유실이 생기지 않는 순서여야 한다. 원문: ADR 013, 022, 035, `docs/알림-멱등-가드.md`.
- 발송 경로는 수신자, 채널, 주소, 내용만 입력으로 받는다. 관리자 분기 같은 특수 처리를 넣지 않는다. 원문: `AGENTS.md` 구조 규칙.
- 실제 비밀 값(토큰, 비밀번호, 개인 키, webhook 주소)을 코드, 커밋되는 설정, 로그에 넣지 않는다. 테스트 전용으로 만든 값은 해당하지 않는다. 저장소 문서에 이 규칙의 원문이 없어 이 줄이 원본이다.

### P1로 보는 것

코드 모양:

- aggregate와 entity는 `class`, `private constructor`, companion 팩터리다. 신규 생성과 `restore`를 나누고, 모든 필드는 `val`이며, 변경 메서드는 새 인스턴스를 반환한다. 원문: `docs/개발가이드.md` 도메인 모델 관례.
- 시간은 application이 `Clock`으로 만들어 넘긴다. 도메인 코드에 `Instant.now()`를 쓰지 않는다. 원문: `docs/개발가이드.md` 도메인 모델 관례.
- 파생 값은 저장 필드가 아니라 파생 프로퍼티로 둔다. 원문: `docs/개발가이드.md` 도메인 모델 관례.
- application 예외는 모듈의 추상 예외를 상속하고 `errorCode`를 가진다. 에러 코드는 번호가 아니라 의미 코드다. 원문: `docs/개발가이드.md` 예외 관례.
- 인바운드 어댑터는 요청 DTO를 command/query로 바꿔 유스케이스 포트를 부른다. 도메인 규칙을 직접 구현하지 않는다. 원문: `docs/개발가이드.md` 어댑터 관례, `docs/아키텍처.md` Layer Responsibility.
- 외부 실패는 어댑터가 한 번 호출하고 분류해 실패 모델로 바꾼다. 어댑터 안에 in-process 재시도 루프를 두지 않는다. 원문: `docs/개발가이드.md` 어댑터 관례.
- internal API는 `ApiPaths`, `ApiVersions`, `ApiResponse`를 따르고, 컨트롤러는 `/api` prefix를 직접 갖지 않는다. 원문: `docs/개발가이드.md` 어댑터 관례, `docs/아키텍처.md` API 버전 정책.
- 서비스 간 공유 모듈은 이벤트 계약 모듈(`*-contract`)뿐이다. 원문: `docs/개발가이드.md` 기술 스택.
- 포트, 유스케이스, 어댑터, 예외, 에러 코드의 이름은 정해진 꼴을 따른다. 수신자 용어는 `recipientId`, `channel`, `address`뿐이고 합성어와 리터럴 `admin`을 쓰지 않는다. 원문: `docs/개발가이드.md` 네이밍, `AGENTS.md` 구조 규칙.
- KDoc은 "왜"를 적고, 소스 주석은 그 파일의 책임만 말하며, 코드가 보여 주는 것을 되풀이하지 않는다. 원문: `docs/개발가이드.md` 주석 관례, `jvm-conventions` 스킬(`$HOME/.agents/skills/jvm-conventions/SKILL.md`).
- 옛 데이터 호환 코드(nullable 필드, fallback, 옛 형식 문서를 위한 테스트)를 넣지 않는다. 원문: `.agents/tech-critic-beliefs.md` 이 저장소에서 특히 거부하는 것.

배치(ArchUnit이 보지 않는 부분):

- 포트의 파라미터·리턴 타입은 `<feature>/model/`에, 요청·응답 DTO는 컨트롤러 옆에, vendor의 요청·응답 타입은 `dto/`에 둔다. 원문: `docs/패키지구조.md` application/port, adapter/inbound, adapter/outbound.
- adapter와 application은 `*Properties`를 받지 않는다. config의 `@Bean`이 값을 넘긴다. 원문: `docs/패키지구조.md` config.
- `src/test`는 main 패키지를 미러하고, test 루트에는 `fake/`, `fixture/`, `support/`, `architecture/`를 둔다. 원문: `docs/패키지구조.md` 테스트.
- 패키지를 옮긴 diff는 문서의 경로 참조도 함께 고친다. 원문: `.agents/tech-critic-beliefs.md` 이 저장소에서 특히 거부하는 것.

테스트:

- 실제 인프라가 붙는 테스트는 `*IntegrationTest`이고 Testcontainers로 인프라를 직접 띄운다. 인프라나 Docker가 없으면 skip이 아니라 실패한다. 원문: `docs/테스트전략.md` 테스트 분류, 인프라 테스트 기준, Testcontainers 정책.
- 시간에 기대는 테스트는 모듈 fixture의 `NOW`, `CLOCK`을 쓰고 시나리오 시각은 `NOW.plus(...)`로 적는다. 원문: `docs/테스트전략.md` 고정 시간(Clock) 정책.
- application service 단위 테스트는 Fake 포트 구현으로 쓴다. 도메인 테스트는 전이마다 원본 인스턴스가 그대로인지 한 번은 assert한다. 원문: `docs/개발가이드.md` 테스트 관례, 도메인 모델 관례.

문서:

- 도메인 규칙(불변식, 상태 전이)을 바꾼 diff는 해당 `docs/도메인모델-*.md`를 함께 고친다. 새 도메인 개념은 `docs/용어사전.md`에도 올린다. 원문: `docs/README.md` 문서와 책임, 도메인모델 문서 규칙.
- 동작을 바꾼 diff는 그 동작을 설명하는 기존 ADR 본문을 최종 상태로 고친다. ADR에 "개정" 절과 상태 줄을 두지 않는다. 원문: `docs/README.md` ADR 규칙, `.agents/tech-critic-beliefs.md` 기획 문서와 ADR 위치.
- 문서 diff는 문체, 기호, 용어 규칙을 따른다. 원문: `WRITING.md`.

작업 범위:

- task phase의 scope와 "하지 말아야 할 것"을 벗어난 변경. 근거는 그 phase 파일이다.

### P2로 보는 것

- 같은 모듈 안 중복 코드, 쓰이지 않는 코드, 이름이 뜻을 덜 드러내는 경우.
- 테스트 이름이 검증하는 규칙을 말하지 않는 경우.

## 못 본 범위

응답에 아래를 빠짐없이 적는다.

- 읽지 않은 변경 파일과 그 이유(생성 파일, 크기, 이진 파일).
- 읽지 않은 원문 절. diff가 닿지 않아 읽지 않은 절도 적는다.
- 실행하지 않은 검증. 리뷰어는 테스트를 실행하지 않으므로 테스트 통과 여부는 항상 못 본 범위다.
- 근거 절이 없어 판단을 보류한 항목. 이것은 질문으로도 올린다.
